# 은빛성가

함께 걷고, 조용히 쉬어가는 전체 화면 3D 성당 공간입니다. 1인칭·3인칭 시점을 전환하고, 같은 공간의 이용자와 산책하거나 기도할 수 있습니다. 외부 라이브러리·CDN·이미지·모델 다운로드 없이 브라우저 WebGL로 렌더링합니다.

## 실행

Node.js 18 이상에서 의존성 설치 없이 실행합니다.

```bash
npm run dev
```

http://localhost:5173 에 접속하세요. 다른 포트는 `PORT=3000 npm run dev`로 지정합니다.

## Docker 배포 테스트

ZIP을 해제한 뒤 `eunbit-seongga` 폴더에서 실행합니다. 기존 컨테이너가 실행 중이라면 해당 배포 폴더에서 `docker compose down`으로 중지한 뒤 새 폴더에서 실행하세요.

```bash
docker compose up -d --build
```

http://localhost 에 접속하세요. 다른 기기로 접속할 때는 같은 서버의 IP 또는 도메인을 사용하고 80 포트 접근을 허용하세요. 휴대폰에서 `localhost`는 휴대폰 자신을 가리킵니다.

```bash
docker compose ps
docker compose logs -f
# 테스트 종료
docker compose down
```

Compose 없이 실행하는 방법:

```bash
docker build -t eunbit-seongga .
docker run -d --name eunbit-seongga -p 80:3000 eunbit-seongga
# 테스트 종료
docker rm -f eunbit-seongga
```

초기 Node 이미지 다운로드에는 네트워크가 필요합니다. 포트 매핑은 **호스트 80 → 컨테이너 3000**입니다. 주소에 포트를 붙이지 않아도 접속할 수 있습니다. 80 포트를 사용하는 기존 서비스가 있다면 먼저 포트 사용을 해제하세요. 서버에 GPU는 필요하지 않으며, 방문자의 브라우저가 WebGL을 지원해야 합니다. 비관리자 사용자로 실행하고 HTTP 헬스체크를 포함합니다.

## 성당 공간

제대와 십자가, 장미창과 스테인드글라스, 첨탑과 종탑, 아치 기둥, 대리석 바닥과 중앙 통로를 3D 모델로 구성했습니다. 중앙 통로 양옆의 나무 의자는 총 8개 긴 좌석, 24개 앉을 위치로 배치했습니다. 의자를 선택하면 중앙 통로를 통해 자리로 이동합니다. 3인칭에서는 지붕을 생략해 내부를 보여주는 단면 시점, 1인칭에서는 지붕까지 표시하는 눈높이 시점을 사용합니다.

기도 버튼을 누르면 두 손을 모으고, 다시 누르거나 이동하면 기도를 마칩니다. 이 동작을 다른 접속자에게도 동기화합니다. 묵주는 십자가와 59개 구슬로 표시하고 진행한 구슬을 강조합니다. 기도문을 자동 낭송하거나 전례 순서를 진행하는 기능은 포함하지 않습니다. 종 버튼은 개인에게만 들리는 합성 종소리입니다.

## 조작

- **우측 상단 1인칭 / 3인칭 버튼 또는 V**: 시점 전환
- **WASD / 방향키**: 카메라 방향 기준 이동
- **모바일 조이스틱**: 연속 이동
- **드래그**: 주변을 둘러보기·시점 회전
- **마당 클릭 / 터치**: 목적지로 이동
- **휠 / 두 손가락 벌리기**: 3인칭 확대·축소
- **R / 시점 초기화 버튼**: 카메라 방향 초기화
- **전체 화면 버튼**: 지원 브라우저에서 주소창까지 숨기는 전체 화면
- **성당 의자 클릭 / 1 / Space**: 앉기·일어나기
- **2**: 두 손을 모아 기도하기·마치기
- **3**: 묵주, 클릭·드래그로 한 알씩 넘기기
- **4**: 개인 성당 종 소리

1인칭에서는 내 캐릭터와 이름표를 숨기고 캐릭터 눈높이에서 바라봅니다. 앉으면 시점이 낮아집니다. 접속 즉시 3D 공간이 브라우저 전체를 채우며 모바일 세로·가로, 노치·홈 영역에 대응합니다. 기도 기록은 날짜별로 브라우저에 저장하고 안내 창에서 초기화할 수 있습니다.

## 함께 머물기

같은 서버·같은 공간에 접속하면 실제 다른 이용자의 캐릭터와 이름표가 나타납니다. 이동·앉기·기도하기를 동기화하며, 장식용 인원을 접속 인원에 포함하지 않습니다. 임시 이름은 서버가 부여합니다. 방은 빛의 성당(낮), 달빛 성당(밤), 빗소리 성당(비)로 구분하고 각각 최대 32개의 동시 세션을 허용합니다. 인원수는 사람 수가 아닌 브라우저 접속 세션 수입니다.

공간 선택 창에서 **이 공간의 초대 링크 복사**를 누르면 방 정보가 포함된 링크를 공유할 수 있습니다. 다른 브라우저·시크릿 창·휴대폰에서 같은 링크를 열어 함께 테스트하세요. 링크 복사가 차단되면 복사할 주소를 안내합니다. 채팅·계정·공용 소리는 포함하지 않습니다.

실시간 연결은 SSE 수신과 초당 최대 10회 HTTP 상태 전송을 사용합니다. 서버는 5Hz 상태를 전송하고 클라이언트는 위치를 보간합니다. 접속 세션 토큰, 방 분리, 좌표 범위·이동 속도 제한, 잘못된 입력 검증, 요청 간격 제한, 접속 종료·유휴 세션 정리, 자동 재연결을 포함합니다. 네트워크가 끊기면 혼자 계속 사용할 수 있습니다.

**운영 범위:** Node 프로세스·Docker 컨테이너 한 개를 사용하는 메모리 기반 동기화입니다. 서버 재시작 시 세션은 초기화됩니다. 32명은 입장 제한값으로, 부하 시험을 거친 수용량 보장은 아닙니다. 여러 컨테이너 운영에는 공유 상태·중계 계층이 추가로 필요합니다. 역방향 프록시를 둔다면 `/api/events`의 SSE 버퍼링을 끄고 지속 연결을 허용하세요. 서버는 `X-Accel-Buffering: no`를 전송합니다. 충돌 처리는 클라이언트의 단순 장애물 검사이며, 의자 선택 시 중앙 통로를 지나는 고정 이동 경로를 사용합니다. 일반 클릭 이동의 자동 우회 경로 탐색이나 이용자 간 물리 충돌은 포함하지 않습니다.

## 구성과 검증

- `engine.js`, `world.js`: WebGL 렌더러와 3D 모델
- `camera.js`, `app.js`: 시점·조작·기도·오디오·기록
- `network.js`, `multiplayer.js`, `server.mjs`: 접속·공간 동기화·HTTP 서버
- `index.html`, `style.css`: 전체 화면·모바일 HUD
- `tests/`: 좌표·모델, 1인칭 카메라, 세션·방 분리·입력 검증·재연결 상태 검사

```bash
npm run check
npm test
docker compose config --quiet
```

작성 환경에서 서버 포트 열기, Chromium 실행, Docker 데몬 접근이 차단되어 실제 여러 브라우저 간 통신·GPU 렌더링·모바일 조작·컨테이너 실행은 검증하지 못했습니다. 자동 검사는 카메라 계산, 모델·세션 로직, 24개 의자 자리의 이동 경로, 네트워크 이벤트 스텁을 포함합니다. 별도 DOM/WebGL 스텁으로 기도 전환, 묵주 진행과 전체 게임 프레임도 검사했지만 실제 GPU 렌더링을 확인한 것은 아닙니다.
